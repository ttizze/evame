# 公開HTMLとデータ更新

## 配信経路

公開トップ・記事・著者・新着・タグ・About・規約はAstroで本文と一覧を最初のHTMLに含める。R2に有効なHTMLがあればPublicPages entrypointの実行とDB取得を省略する。HTMLがない場合や関連する変更記録があれば、同じWorker内でDBを読みAstroで描画する。全URLの事前生成・生成用Cron・Queueは使わない。画像用R2は維持する。

`src/server.ts` はメンテナンス判定後、公開GET/HEADを `src/app/_infra/reader-html.ts` へ渡す。R2 GET一回で保存HTMLを読み、必要な場合だけ同じWorkerの `PublicPages` entrypointでDB接続・Astro生成を行う。外側の応答は言語Cookieを含むため `private, no-store` とする。R2のHTMLは時間経過やWorkerデプロイでは失効させない。Reader専用WorkerとGateway専用Workerは置かない。閲覧数・いいねの即時表示はprivate APIで取得する。人気順はいいね数の降順、同数なら作成日時・IDの降順であり、いいね・解除・公開状態の変更を受けてhomeと著者一覧を無効化する。

トップは `reader/src/components/home.astro` と `home-pages.astro` で一覧を描画し、一覧全体のReact hydrationを行わない。`home-feed.client.ts` が30秒ごととウィンドウのフォーカス復帰時にReaderの `/api/home-feed?locale=...` から最新の一覧HTMLを取得する。部分更新も同じ `home-pages.astro` とカードを使用する。同じ内容ならDOMを交換せず、更新失敗時は表示済みHTMLを残して再試行を受け付ける。一覧内で操作中のフォーカスは奪わない。部分更新は共有キャッシュへ保存しない。部分更新も同じWorker内でDBを読みAstroで描画する。

Cookieバー・一覧のアバター・いいね・共通ヘッダー・トップの浮動バーのスクロール処理は、配信済みHTMLとcustom elementで動作する。`reader/src/client.ts` が初期化を所有し、記事が0件の初回表示から追加された場合も動作する。カードのいいねは `page-likes.client.ts` が一括取得し、同じ記事が新着と人気へ重複しても両方を更新する。本文のいいね・コメントなどは既存のReact islandを維持する。

ヘッダーは `/api/reader-header?locale=...` をHTMLのfetch preloadで先行取得する。`credentials: include` に合わせ、表示時にその応答を再利用する。このprivate APIのJSONは本人の表示名・ハンドル・画像・プラン・APIキーの有無・未読件数だけを返し、メールアドレスやセッションを返さない。Better Authの `returnHeaders` で受け取ったCookieをHTTPヘッダーへ引き継ぎ、閲覧中の期限延長と無効なセッションCookieの削除を維持する。更新対象のセッションで、実APIがCookieを返し、DBの有効期限を7日間へ延長することも検証する。通知一覧と件数のSQLは `src/app/api/_db/notifications/queries.ts` で参照先の有効条件を共有する。共有HTMLへ個人情報を埋め込まず、ブラウザーごとに取得し、二重取得がないこともブラウザーテストで確認する。

トップのログイン・言語・使い方・浮動バーは `client:interaction` で最初の操作を引き継いで起動し、アカウントメニューも初回操作時に起動する。ポインターやフォーカスで必要なコードの取得を始める。新規作成と検索リンクはReactを待たない。記事では翻訳状態アイコンと従来のスクロール処理を保つため、言語UIと浮動バーの既存islandを起動する。翻訳追加フォームは初回操作後もマウントを保ち、閉じた後のジョブ監視を維持する。共有先・段落の翻訳フォームも操作時に読み込む。最初のReact islandが共通の通知表示を取得し、最後のislandが外れると破棄する。テーマの初期適用はSSRしたThemeProviderのスクリプトを使い、その後は `reader/src/theme.client.ts` がOS・別タブ・本人の選択を一元管理する。メニューと通知表示は同じ状態を購読し、複数のThemeProviderで上書きしない。

`reader/src/monitoring.client.ts` はFCP後にSentryを取得し、CSSとの通信競合を避ける。SDK起動前のJavaScriptエラーと未処理Promiseを保持し、初期化後に送信する。Paint Timing非対応のブラウザーでは描画フレーム後に起動する。初期化には従来の `src/instrument.client.ts` を使い、計測・リプレイの設定値を維持する。ChromiumとWebKitの両方でSDKの取得も確認する。

`reader/astro.config.mjs` は初回の小さな操作処理と、操作時に使うUI・React DOMを別のチャンクにする。Workers成果物のブラウザーテストでは、ログイン済みトップの初回JSが8要求以内で、操作用のチャンクをまだ読み込まないことを確認する。CSSはハッシュ付きアセットとして長期キャッシュする。全量のインライン化は採用せず、再訪時にHTMLと分けて再利用する。

共通の計測同意は `shared/analytics-consent.ts`、ヘッダーと浮動バーのスクロール判定は `shared/header-scroll-state.ts` と `shared/floating-controls-visible.ts` に置く。Readerのcustom elementと編集・管理側のReact実装という複数の利用箇所で、同意や表示条件がずれないよう純粋な処理だけを共有する。共有UIは `shared/header/*.tsx` を両方から使用し、寸法・アイコン・読み上げ名を揃える。

`reader/src/pages/[...path].astro` はAstro側の共有キャッシュを無効にし、公開結果に依存タグを付ける。R2へ保存するのは200 HTMLで、依存タグがあり、Set-Cookieとprivate/no-storeがない応答だけ。検索・下書きプレビュー・404は保存しない。認証CookieをDB取得へ渡すのは所有者プレビューの判定のためであり、公開HTMLにセッション・個人情報を含めない。

## 対象別の無効化

`reader_revisions` は元の変更と同じDBトランザクションで変更キーを記録する。既存の `0001_reader_publication.sql` を保持し、`0002_reader_cache_dependencies.sql` で一覧の所属、変更前の親、タグ名、著者ハンドル、フォローの当事者を追加する。`0004_reader_r2_publication.sql` はR2反映用のoutboxを追加し、旧purge用の保留表を廃止する。過去のマイグレーション自体は保持する。

| 変更 | 無効化対象 |
| --- | --- |
| 本文・コメント・翻訳・投票 | 対象記事とその記事を掲載する一覧 |
| タイトル・並び順・階層 | 対象記事、影響する階層を表示する記事 |
| 新規公開・非公開化・削除・掲載順変更 | 新着・トップ・対象著者・関連タグの一覧グループ、対象記事 |
| タグの追加・削除・改名 | 記事と変更前後のタグ一覧 |
| 表示名・ハンドル・画像など | 著者を表示する記事・一覧・フォロワー欄・階層 |
| フォロー・解除 | 当事者のプロフィール |
| 集計に関係する変更 | About |

本文だけの編集で、無関係な記事や新着の全ページを消さない。一覧の件数・順序が変わる場合は一覧グループをタグで無効化する。新着・著者一覧は親記事を対象にするが、タグ一覧は子記事の公開・非公開化・削除や見出しの追加も対象にする。154ページの新着一覧があっても154ページを列挙・生成しない。次に閲覧されたURLだけが再描画される。

`src/db/queries.ts` は保存入口から使うDB読み取り境界。DB更新と同時にoutboxへ記録された変更キーを取得し、階層変更のあった記事だけを再帰SQLで親方向へ辿る。移動前の親も記録するため、移動・削除後も古い階層を無効化できる。R2へ反映したキーと版が一致する行だけを削除し、同時保存の後続変更を残す。

`load-reader-data.ts` は読み取った表示データに必要な依存キーを付ける。カードの掲載記事・著者、コメント著者、プロフィールのフォロー相手、階層の親を含み、空の一覧にもグループキーを付ける。タグ数がCloudflareの上限を超える応答は共有キャッシュへ入れない。

`src/app/_domain/reader-cache-tags.ts` は読み取り側のAstroと書き込み側の保存APIで共用する純粋な変換。日本語・カンマ・大小文字を含むキーをSHA-256の固定長タグへ変換する。Cloudflareのタグ制約や大小文字を区別しない照合で別の対象が衝突しないよう、両方で同じ変換を使う。

保存後にoutboxの変更キーと版を取得し、同じWorkerの `PublicPages.publish(changes)` をRPCで呼ぶ。`changes/<DB URL hash>/<revision>/<tag hash>` をR2へ追記し、成功を待って保存成功を返す。R2反映に失敗したらoutboxを残し、DB差分のない同内容再保存でも再送する。取得した版だけを完了扱いにするため、同じタグの後続変更を消さない。下書き保存・画像アップロード・APIキー・翻訳投入では公開HTMLを生成しない。

HTMLには生成前のDB版と固有の生成識別子を保存する。DB取得前に生成中索引を作り、依存キーごとの完成済み索引を保存してからHTMLを条件付きPUTし、生成中索引を削除する。保存側は生成中→該当依存キーの完成済み索引の順でLISTを全ページたどり、版・生成識別子・ETagを照合して対象だけを無効化する。通常のHITでLISTは行わない。古い生成の遅延完了や変更記録の到着順逆転でも最新本文・非公開化を巻き戻さない。HTMLと依存索引に削除期限は設けず、変更マーカーと生成中索引だけを2日で回収する。異なるDBは全prefixで分離する。

## デプロイ

1. バケット作成時の初期設定でHTML・依存索引・アセットの削除lifecycleを外す。
2. DBマイグレーションを実行する。
3. ハッシュ付きアセットをR2 bindingへ保存し、失敗時はデプロイしない。
4. AstroとTanStack Startを含む `dist/server/wrangler.json` を `evame-start` へ1回デプロイする。HTML保存先は維持し、一括purgeやHTMLの事前生成は行わない。

JS/CSSはHTMLと同じWorkerから配信する。現行Static Assetsが404を返す旧ハッシュ付きアセットはR2から取得し、保存HTMLと同じく削除期限を設けない。保存時は対象タグを無効化し、コード更新だけではHTMLを失効させない。固定文言・テンプレートを反映する場合は対象HTMLを明示的に削除して次のGETで生成する。R2 bucketとlifecycleの準備は[Cloudflare運用](../howto/cloudflare-workers.md)を参照する。

## 検証

DBテストで本文・公開状態・タイトル翻訳・階層移動と削除・タグ削除・著者変更・フォロー解除を確認する。成果物テストは768件の追加記事がある状態でも公開記事を保存し、本文SSR、編集・公開・非公開化・削除を確認する。ブラウザーではLexical、コメントと返信、言語選択、Cookieバー、浮動バー、目次、アイコン、プロフィール、JavaScript無効のコメント途中ページを確認する。ローカルのSentry送信はサーバーとブラウザーの両方で無効にする。

実R2のHITと対象別の変更反映はCloudflare上で検証する。対象記事・一覧の更新後に新しい本文や非公開状態が返り、無関係な記事のキャッシュが残ることを確認する。ローカルテストだけでCloudflare上の検証済みとはしない。

### トップのブラウザー計測（2026-11-13）

main `0528c19e` と、同じmainに本変更を適用した最終ビルドを比較した。どちらもAstroのキャッシュ付きSSR。ローカルのGateway・Reader・libSQLに公開記事10件を置き、Chromiumで各条件を5回測定した平均値。PCは1280×900、スマホは390×844、CPUは4倍減速。HTTPS・HTTP/2のプロキシでHTML・CSS・JS・JSONをgzipし、応答ヘッダーを100ms遅らせ、圧縮後の本文を合計200,000 B/sで送信した。ブラウザーの通信制限との二重適用はしない。Cookie同意は未選択、外部通信とSentry送信は無効とした。
