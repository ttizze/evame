# 公開HTMLとデータ更新

## 配信経路

公開トップ・記事・著者・新着・タグ・About・規約はAstroで本文と一覧を最初のHTMLに含める。Cloudflare Workers Cacheに命中すればReaderの実行とDB取得を省略する。キャッシュミス時だけReaderから非公開のReaderBackendを呼び、DBを読み、Astroで描画する。HTMLのR2保存、全URLの事前生成、生成用Cron・Queueは使わない。画像用R2は維持する。

Gateway (`src/server.ts`) はメンテナンス判定後、公開GET/HEADをDB接続なしでReaderへ渡す。Gatewayの応答は言語Cookieを含むため `private, no-store` とし、共有HTMLのキャッシュはReaderだけが所有する。ReaderのHTMLは1時間キャッシュする。閲覧数・いいねの即時表示はprivate APIで取得する。人気順のSSRはキャッシュ期限で再取得する。

トップは `reader/src/components/home.astro` と `home-pages.astro` で一覧を描画し、一覧全体のReact hydrationを行わない。`home-feed.client.ts` が30秒ごととウィンドウのフォーカス復帰時にReaderの `/api/home-feed?locale=...` から最新の一覧HTMLを取得する。部分更新も同じ `home-pages.astro` とカードを使用する。同じ内容ならDOMを交換せず、更新失敗時は表示済みHTMLを残して再試行を受け付ける。一覧内で操作中のフォーカスは奪わない。部分更新は共有キャッシュへ保存しない。Gatewayはアセットと同じReaderへの転送経路を使い、DB接続と描画はReaderBackendとAstroが所有する。

Cookieバー・一覧のアバター・いいね・共通ヘッダー・トップの浮動バーのスクロール処理は、配信済みHTMLとcustom elementで動作する。`reader/src/client.ts` が初期化を所有し、記事が0件の初回表示から追加された場合も動作する。カードのいいねは `page-likes.client.ts` が一括取得し、同じ記事が新着と人気へ重複しても両方を更新する。本文のいいね・コメントなどは既存のReact islandを維持する。

ヘッダーは `/api/reader-header?locale=...` をHTMLのfetch preloadで先行取得する。`credentials: include` に合わせ、表示時にその応答を再利用する。このprivate APIのJSONは本人の表示名・ハンドル・画像・プラン・APIキーの有無・未読件数だけを返し、メールアドレスやセッションを返さない。Better Authの `returnHeaders` で受け取ったCookieをHTTPヘッダーへ引き継ぎ、閲覧中の期限延長と無効なセッションCookieの削除を維持する。更新対象のセッションで、実APIがCookieを返し、DBの有効期限を7日間へ延長することも検証する。通知一覧と件数のSQLは `src/app/api/_db/notifications/queries.ts` で参照先の有効条件を共有する。共有HTMLへ個人情報を埋め込まず、ブラウザーごとに取得し、二重取得がないこともブラウザーテストで確認する。

トップのログイン・言語・使い方・浮動バーは `client:interaction` で最初の操作を引き継いで起動し、アカウントメニューも初回操作時に起動する。ポインターやフォーカスで必要なコードの取得を始める。新規作成と検索リンクはReactを待たない。記事では翻訳状態アイコンと従来のスクロール処理を保つため、言語UIと浮動バーの既存islandを起動する。翻訳追加フォームは初回操作後もマウントを保ち、閉じた後のジョブ監視を維持する。共有先・段落の翻訳フォームも操作時に読み込む。最初のReact islandが共通の通知表示を取得し、最後のislandが外れると破棄する。テーマの初期適用はSSRしたThemeProviderのスクリプトを使い、その後は `reader/src/theme.client.ts` がOS・別タブ・本人の選択を一元管理する。メニューと通知表示は同じ状態を購読し、複数のThemeProviderで上書きしない。

`reader/src/monitoring.client.ts` はFCP後にSentryを取得し、CSSとの通信競合を避ける。SDK起動前のJavaScriptエラーと未処理Promiseを保持し、初期化後に送信する。Paint Timing非対応のブラウザーでは描画フレーム後に起動する。初期化には従来の `src/instrument.client.ts` を使い、計測・リプレイの設定値を維持する。ChromiumとWebKitの両方でSDKの取得も確認する。

`reader/astro.config.mjs` は初回の小さな操作処理と、操作時に使うUI・React DOMを別のチャンクにする。Workers成果物のブラウザーテストでは、ログイン済みトップの初回JSが8要求以内で、操作用のチャンクをまだ読み込まないことを確認する。CSSはハッシュ付きアセットとして長期キャッシュする。全量のインライン化は採用せず、再訪時にHTMLと分けて再利用する。

共通の計測同意は `shared/analytics-consent.ts`、ヘッダーと浮動バーのスクロール判定は `shared/header-scroll-state.ts` と `shared/floating-controls-visible.ts` に置く。Readerのcustom elementと編集・管理側のReact実装という複数の利用箇所で、同意や表示条件がずれないよう純粋な処理だけを共有する。共有UIは `shared/header/*.tsx` を両方から使用し、寸法・アイコン・読み上げ名を揃える。

`reader/src/pages/[...path].astro` は公開結果だけを共有キャッシュへ入れる。検索・下書きプレビュー・404はキャッシュしない。ローカルで `cache.purge` がない場合も共有キャッシュを無効にする。認証CookieをDB取得へ渡すのは所有者プレビューの判定のためであり、公開HTMLにセッション・個人情報を含めない。

## 対象別の無効化

`reader_revisions` は元の変更と同じDBトランザクションで変更キーを記録する。既存の `0001_reader_publication.sql` を保持し、`0002_reader_cache_dependencies.sql` で一覧の所属、変更前の親、タグ名、著者ハンドル、フォローの当事者を追加する。過去のマイグレーションや旧Workerの参照列は削除しない。

| 変更 | 無効化対象 |
| --- | --- |
| 本文・コメント・翻訳・投票 | 対象記事とその記事を掲載する一覧 |
| タイトル・並び順・階層 | 対象記事、影響する階層を表示する記事 |
| 新規公開・非公開化・削除・掲載順変更 | 新着・トップ・対象著者・関連タグの一覧グループ、対象記事 |
| タグの追加・削除・改名 | 記事と変更前後のタグ一覧 |
| 表示名・ハンドル・画像など | 著者を表示する記事・一覧・フォロワー欄・階層 |
| フォロー・解除 | 当事者のプロフィール |
| 集計に関係する変更 | About |

本文だけの編集で、無関係な記事や新着の全ページを消さない。一覧の件数・順序が変わる場合は一覧グループをタグで無効化する。新着・著者一覧は親記事を対象にするが、タグ一覧は子記事の公開・非公開化・削除や見出しの追加も対象にする。154ページの新着一覧があっても154ページを列挙・生成しない。次に閲覧されたURLだけが再描画される。

`src/db/queries.ts` はGatewayから使うDB読み取り境界。保存開始時の版より新しい変更キーをインデックスで取得し、階層変更のあった記事だけを再帰SQLで親方向へ辿る。移動前の親も記録するため、移動・削除後も古い階層を無効化できる。同時保存の変更が含まれる場合は両方を削除する。

`load-reader-data.ts` は読み取った表示データに必要な依存キーを付ける。カードの掲載記事・著者、コメント著者、プロフィールのフォロー相手、階層の親を含み、空の一覧にもグループキーを付ける。タグ数がCloudflareの上限を超える応答は共有キャッシュへ入れない。

`src/app/_domain/reader-cache-tags.ts` は読み取り側のAstroと書き込み側のGatewayで共用する純粋な変換。日本語・カンマ・大小文字を含むキーをSHA-256の固定長タグへ変換する。Cloudflareのタグ制約や大小文字を区別しない照合で別の対象が衝突しないよう、両方で同じ変換を使う。

Gatewayは保存後に変更キーを取得し、Readerの非公開 `/__invalidate` へタグだけを渡す。Reader自身が `cache.purge` を実行し、成功を待って保存成功を返す。無効化に失敗したら成功扱いにしない。削除要求の前に `reader_cache_invalidations` へ対象タグと要求の版を保存し、成功後にその版だけを消す。削除失敗後は、DBの差分がない再試行でも保留タグを再送する。古い要求の成功通知で、同じタグに重なった後続の変更を消さない。下書き保存ではReaderを呼ばず、保留タグは公開内容の更新を扱う次の操作で再送する。下書きの自動保存、画像アップロード、APIキー、翻訳の投入だけでは共有HTMLを削除しない。HTMLの生成は保存処理に含めない。

Workers Cacheのpurgeには、プランによらずFree枠の継続5要求/分・バースト25要求・1要求100対象という[上限](https://developers.cloudflare.com/workers/cache/purge/#rate-limits)がある。既存の全体purgeにも適用される制約で、対象別タグへの変更で回数上限自体は増えない。削除が拒否された場合も保留タグを残し、保存成功にしない。多人数による継続的な公開更新では、この上限を別途配信基盤の選定条件とする。

## デプロイ

1. 後方互換のDBマイグレーションを先に実行する。
2. 旧Gatewayに対応するReaderを先にデプロイする。旧Backendに依存キーがない間も全体タグを付け、旧Gatewayの本文なしの無効化要求を受け付ける。
3. Gatewayをデプロイする。新Gatewayは対象タグだけを送る。
4. 更新成功後にアセット履歴を確定し、`scripts/purge-reader-cache.mjs` から認証済みの一時プレビュー経由で非公開Readerのキャッシュを無効化する。HTMLは生成しない。

JS/CSSはHTMLと同じReaderから配信する。旧HTMLが参照するハッシュ付きアセットも配信終了から30日間保持する。デプロイ用の全体無効化と、保存時の対象別無効化は用途が異なる。`evame-reader` 全体タグはローリング更新とデプロイ時の削除のために維持する。

## 検証

DBテストで本文・公開状態・タイトル翻訳・階層移動と削除・タグ削除・著者変更・フォロー解除を確認する。成果物テストは768件の追加記事がある状態でも公開記事を保存し、本文SSR、編集・公開・非公開化・削除を確認する。ブラウザーではLexical、コメントと返信、言語選択、Cookieバー、浮動バー、目次、アイコン、プロフィール、JavaScript無効のコメント途中ページを確認する。ローカルのSentry送信はサーバーとブラウザーの両方で無効にする。

実CDNのHITと対象別purgeはCloudflare上で検証する。対象記事・一覧の更新後に新しい本文や非公開状態が返り、無関係な記事のキャッシュが残ることを確認する。ローカルテストだけでCDN検証済みとはしない。

### トップのブラウザー計測（2026-11-13）

main `b943ea96` と、同じmainに本変更を適用した最終ビルドを比較した。どちらもAstroのキャッシュ付きSSR。ローカルのGateway・Reader・libSQLに公開記事10件を置き、Chromiumで各条件を5回測定した平均値。PCは1280×900、スマホは390×844、CPUは4倍減速。HTTPS・HTTP/2のプロキシでHTML・CSS・JS・JSONをgzipし、応答ヘッダーを100ms遅らせ、圧縮後の本文を合計200,000 B/sで送信した。ブラウザーの通信制限との二重適用はしない。Cookie同意は未選択、外部通信とSentry送信は無効とした。
