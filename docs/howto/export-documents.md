# 文書と画像の一括書き出し

ログインして自分の文書管理画面を開き、「Markdown＋画像を書き出す」を押す。ZIPを展開すれば、文書と保存済みの画像を手元に置き、通常のGitリポジトリへ追加できる。

## 対象

- 自分の全ての原文。公開・非公開・アーカイブ済みを含み、管理画面の検索条件や表示中のページには限定しない。
- EvameのR2へ保存された画像の原本。同じ画像はZIP内に一度だけ格納する。
- 本文中のMarkdown画像、参照形式の画像、生HTMLの`img`に対応する。

翻訳、コメント、投票、編集履歴は含まない。文書と画像の持ち出し用であり、DB全体の復元用バックアップではない。

## ZIPの内容

- `documents/<文書ID>-<slug>.md`: 原文のMarkdown。タイトル、元のslug、言語、公開状態、コメント受付、親文書ID、公開・作成・更新日時、タグをYAML frontmatterに保存する。タイトルの変更でファイル名は変わらない。
- `images/`: 保存済み画像。Markdownからの参照は`../images/...`へ書き換える。
- `export-report.json`: 文書と画像の件数、同梱できなかった画像、書き出し中に削除された文書ID。
- `README.md`: 書き出し形式の説明。

外部サイト上の画像や埋め込みは元のURLを保持する。R2から画像を取得できない場合も元のURLを残し、レポートへ記録する。元の文書や画像を変更・削除することはない。

## 動作

認証されたユーザーの文書だけを読み、文書と画像を1件ずつZIPへ流す。全画像をWorkersのメモリへ溜めない。ZIPライブラリはZip64とWeb Streamsに対応するものを使う。

文書をMarkdownへ変換できない場合は、空本文や不完全なZIPを成功としてダウンロードさせず、書き出しを失敗させる。画像を同梱できない場合は本文の参照先を維持してレポートへ記録する。

書き出し開始時に対象文書IDを取得し、各文書を読む時点の内容を含める。全アカウントを一時停止した単一時点のDBスナップショットではない。

`GET /api/export-pages`はCookieによるログインを必要とし、`private, no-store`を付ける。未認証の場合は401を返す。任意のユーザーIDを指定して別の利用者の文書を取得することはできない。
