# ComrakのiPhone向け評価

Comrak **0.59.0**をRust **1.98.0**で固定した、アプリから独立した検証。解析・Markdown出力・ASTの文字変更を調べる。iPhoneアプリの採用・移行は行っていない。配信済みアプリのJavaScriptCore依存もこの検証では変わらない。

## 再実行

macOSのArm64、Xcode 26.6 (17F113)、iOS Simulator 26.5で実行する。既存のシミュレーターUUIDを指定する。

```sh
nix develop .#comrak --command bash scripts/ios.sh comrak-probe <simulator UUID>
```

Nixの`comrak`シェルからRustupを使い、`rust-toolchain.toml`でコンパイラー・コンポーネント・iOSターゲットを固定する。Cargoの全依存は`Cargo.lock`で固定する。ホストの集計に必要な既存Bun依存はルートで`bun install --frozen-lockfile`を実行する。ComrakのCLI・シンタックスハイライトは組み込まない。

`target/corpus.json`に公式全例の入出力、`target/report.json`に差が出る全例と集計を生成する。BunはホストでのHTML比較だけに使う。Swift/C/Rustの実行経路にJavaScriptはない。

**現在の終了コードは101**。受け入れ条件を満たさないテストがあるためであり、不一致を無視して成功扱いにはしない。失敗後も独立したSwift/iOS接続検証まで進め、最後に元の失敗コードを返す。この評価用コマンドは既存アプリの通常CIの合否とは別である。

公式集合の集計自体は、比較の不一致を終了コード2で返す。依存不足やJSON破損などの実行エラーは即座に失敗させ、評価結果と混同しない。

## 結果（2026-11-08）

| 検証 | CommonMark 0.31.2 | GFM 0.29 |
| --- | ---: | ---: |
| 公式の期待HTMLと文字列一致 | 652 / 652 | 666 / 677 |
| 属性順・void要素の閉じ方を除いたHTML一致 | 652 / 652 | 668 / 677 |
| Markdownへ出力・再解析したHTMLの文字列一致 | 635 / 652 | 660 / 677 |
| 出力・再解析後の比較対象AST一致 | 633 / 652 | 658 / 677 |

HTML比較では本文の空白・改行・コメントを消さない。AST比較ではソース位置、見出しやコードの記法、リストの記号を除外し、本文・書式の入れ子・URL・題名・画像説明の構造・番号・チェック状態・表の配置を比較する。URLの空白が`%20`へ変わる場合も差として記録する。したがってASTの差の件数を、そのまま描画不具合の件数とはしない。

書き出し・再解析の差は、両方の公式集合でそれぞれ次の19例だった。以下の例番号はCommonMark側のもの。

- 複数行のSetext見出しの改行が空白になる3例（CommonMark #81・82・95）。
- 同じ太字の入れ子が一重になる9例（#389・417・425・426・427・464・465・466・468）。
- リストの分離に`<!-- end list -->`が追加される5例（#257・297・301・302・313）。
- URLの空白が`%20`へ正規化される2例（#195・489）。HTMLは同じ。

GFMの解析時の9例のHTML差は次の3種類で、**GFMの公式全例による受け入れは現状満たさない**。チェック項目2例は属性順と`/>`のみの違いだった。CommonMarkの解析は652例すべて公式期待値と一致した。

- 自動リンク6例（#611・617・620・621・634・635）は、リンク化する範囲やURLが公式期待値と異なる。CommonMarkの成功からGFM互換とは判断しない。
- HTMLコメント2例（#649・650）は、GFM 0.29とCommonMark 0.31.2の規則の差を含む。同じ設定で両方へ一致させることはできない。
- tagfilter 1例（#657）は、0.56で拡張が削除された影響。[公式変更履歴](https://github.com/kivikakk/comrak/blob/v0.59.0/CHANGELOG.md)にも記載されている。本検証の`render.unsafe=true`は生HTMLも文字列として比較するための設定であり、選択的なHTMLの無害化は行わない。すべてのHTMLをエスケープする`render.escape`とは異なり、旧GFMのtagfilter互換を確認したものではない。

追加の受け入れテストは**10テスト中8成功・2失敗**。

- 日本語・英字の斜体と太字、文字としてのMarkdown記号、表セルのパイプ、使用中の参照リンクの再編集、画像説明の装飾と入れ子は成功した。
- 先頭の空白4文字を持つ段落は、保存後にインデントコードへ変わる。`&#32;&#32;&#32;&#32;行頭`を解析して書き出すだけでも再現し、AST変更時の位置情報やFFIに依存しない。
- 行末の空白2文字、空白＋タブの接頭辞も往復で保持できなかった。
- 空チェック項目は、埋め草なしの`- [ ]`のまま保存・再解析して保持できた。既存保存形の`- [ ] &#x20;`から埋め草の空白は消えるが、空のチェック項目と後続のチェック状態は残る。埋め草の文字一致を、空項目を保持できない問題とは数えない。

前に候補として挙げた0.55.0でも、同じテスト本体を別の一時ディレクトリで実行し、同じ8成功・2失敗になった。現在の固定版は0.59.0とし、旧版の依存は本検証へ追加しない。

SwiftからC ABIを経由して呼び出す検証は、macOSとiOSシミュレーターの両方で成功。公式1,329例のMarkdown・HTML・AST比較結果がRust単体と一致し、編集5例、空チェック項目2例、埋め込みNULを含むUTF-8、不正入力、結果の解放も確認した。実機用Arm64の静的ライブラリもビルドできた。**実機上の実行・UIKitでの描画や操作・性能はこの検証の対象外**。

## 判断と配置

CommonMarkの解析とSwiftからの直接呼び出しは検証できた。GFMの解析と、入力内容・構造を保存する書き出しの両方に未達があるため、現時点で既存のMarkdown処理の全面置き換えには採用しない。期待値を弱めたり、自作のエスケープ処理を追加したりして合格にはしていない。

ComrakはMarkdownの解析・出力ライブラリであり、Return・Backspace・選択・IME・Undo/Redoなどを提供する編集エンジンではない。この検証は既存のProseMirror操作133件やUIKitの受け入れ試験を代替しない。参照リンクは通常のリンクへ展開される。未使用の参照定義など原文にしかない情報を保持する設計も、ASTへの全面移行前に別途必要となる。

- `src/lib.rs`: Comrakの標準APIを呼ぶ評価処理と、検証専用のC ABI。`src/bin/corpus.rs`と`Probe.swift`から使うため、アプリの`EditorCore`から分離した。
- `tests/roundtrip.rs`: 既存の編集要件を入出力で検証する。満たさない条件は失敗のまま記録する。
- `Probe.swift`と`ComrakProbe.h`: UTF-8のバイト数・NULL・所有権を含むSwift/C接続の検証。アプリへ組み込むAPIの確定ではない。
- `report.mjs`: 既存の公式ケースの期待HTMLと入出力を比較するホスト側の集計。ケースを複製せず`../Tests/EditorCoreTests/Fixtures/Upstream`を読む。出典とライセンスは[既存の説明](../README.md#受入確認)に従う。
- `run.sh`: 上記の検証とApple向けビルド。入口は`scripts/ios.sh`。

`semantic_tree`は元ASTと再解析ASTから使用する比較専用関数。同じ除外規則にしないと、ソース位置などの記法上の違いをデータ損失と誤認するため一箇所に置く。`evaluate`はRustのテスト・全例検証・Swift/C接続から使用し、全経路で同じオプションと標準APIを評価するため共有する。
